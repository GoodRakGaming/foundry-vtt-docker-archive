# Foundry VTT Docker Migration — архив

**Статус: заморожено.** Проект признан неактуальным для текущих нужд — сервер вернулся на
предыдущую (не-Docker) схему запуска Foundry VTT. Этот репозиторий сохраняет код в качестве
референса на случай, если потребуется вернуться к идее позже.

## Что это было

Миграция продакшен-сервера Foundry VTT с одного bare-metal процесса на несколько Docker-версий
(v13/v14 и далее), управляемых через две веб-панели:

- **DM-панель** — публичная (Basic Auth), безопасные операции: старт/стоп, переключение активной
  версии, точечный перенос мира между версиями.
- **Admin-панель** — приватная (только через WireGuard), деструктивные операции: деплой новых
  версий, удаление, полная миграция тома, логи, reconcile реестра с диском.

Обе панели общаются не с Docker напрямую, а с привилегированным хелпер-демоном
(`helper/`) через unix-сокеты — один сокет на панель, у каждого свой белый список разрешённых
операций. Это единственный компонент с root-правами; сам факт того, через какой сокет пришёл
запрос, и определяет, что можно, а что нет.

## Структура

```
helper/         — привилегированный демон (root), два unix-сокета (dm/admin), SQLite-реестр
panel-dm/       — express-приложение, публичная панель
panel-admin/    — express-приложение, приватная панель (WireGuard-only)
docker-compose.yml         — снэпшот compose-файла на момент архивации (services для foundry-vN
                              генерируются helper'ом автоматически при деплое, здесь — как было)
foundry-active.conf.example — снэпшот сгенерированного nginx-конфига активной версии
status.md       — полный журнал разработки: что и почему делалось, фазами, включая найденные
                  баги и их починку
```

## Ключевые технические решения (см. status.md за подробностями)

- Реестр (`registry.sqlite`, WAL) — единственный источник истины; `docker-compose.yml` и
  `foundry-active.conf` — производные артефакты, которые хелпер перегенерирует.
- Общие пользовательские ассеты (карты, токены, музыка и т.д.) вынесены в отдельную
  `shared-assets/` и монтируются в каждую версию по тому же относительному пути, что и раньше —
  миры/системы/модули при этом остаются строго версионными (общая система могла бы сломать
  совместимость между v13/v14).
- Guard B: полная миграция тома отказывает, если назначение не пусто — чтобы не затереть данные.
- Foundry сканирует `Data/{worlds,systems,modules}` только при старте процесса — после любого
  копирования в уже запущенный инстанс нужен настоящий `docker compose restart`, не
  `up --no-recreate` (это no-op для уже запущенного контейнера).
- Проверка свободного места перед любой операцией записи (бэкап/копирование/деплой) — раньше её
  почти нигде не было, добавлена по итогам ревью.
- `/app` каждой версии в итоге домонтирован `rw` (не `ro`), чтобы работал встроенный апдейтер
  Foundry — осознанный компромисс: версия перестаёт быть строго неизменной вне контролируемого
  деплоя.

Код не содержит секретов (Basic Auth панели настроен в nginx, вне этого репозитория) и не включает
данные миров, ассеты или сам Foundry VTT (лицензионный продукт — не наш код).
